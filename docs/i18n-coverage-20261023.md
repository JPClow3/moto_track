# English journey coverage (2026-10-23)

English is enabled in `RELEASED_LOCALES` on this development branch so browser
acceptance can exercise negotiation and the selector. Release acceptance remains
pending the root's combined checks and authenticated/public browser evidence;
this flag does not establish a production release.

Implemented in this work:

- Authentication, sign-up, recovery, new passwords and email-verification
  feedback use request-scoped catalogue messages. Known provider error codes
  resolve to reviewed product copy instead of provider prose.
- Landing-page metadata, hero, features, plan segments and footer are translated.
  The blog interface, availability states, comments controls and roadmap use
  reviewed public copy.
- Generic feature forms translate every configured field label, option and
  help string. Submitted option values and route identifiers remain stable.
  Dates and registered enum options in tables use the reader's locale.
- Expenses, professional costs, report filters, sharing controls and public and
  private sale-report interfaces are translated. Shared-garage and maintenance
  phase controls use catalogue keys.
- Rider actions localize only presentation feedback at their response boundary.
  Failure statuses, unrelated response fields, submitted values, redirects,
  ownership checks and persisted notes remain intact. Staff actions can provide
  their own translator to the same boundary helper.
- Workshop comparisons have dedicated complete pt-BR/en messages, voluntary
  consent, review/update/withdrawal and insufficient-data states.
- Legal pages, staff workflows and generated documents have dedicated reviewed
  catalogues from their respective owners.
- Offline pages, empty/loading/error shell states and the language selector use
  the reader's locale. The worker caches two standalone public fallback files,
  without SSR account data, and remembers only the public locale preference.
  An explicit choice wins over the browser language after a worker restart.
- Offline fill-ups persist a stable identifier and originating account before
  synchronization. Redirects, HTML, generic 200s, network failures and malformed
  or mismatched acknowledgements retain the queue item. The network-only PWA
  session check filters foreign-account drafts before any record POST. Replays accept only an
  matching owner and canonical intent, without repeated uploads or preference/
  odometer work. Durable acknowledgements retain only a SHA-256 fingerprint and
  timestamps; deleting the visible record cannot resurrect it on retry. A delete
  of an older unmarked record creates a tombstone with no digest, which blocks
  uncertain replays for manual review. Account deletion removes its markers.
  Legacy entries without an account binding
  remain stored for manual review instead of being assigned to another user.
  The local recovery panel exports, reviews and discards drafts. Importing an
  unassigned legacy draft requires explicit consent for the displayed account,
  preserves its identifier and drops old account-specific relationships.
  Old protocol commits used unrelated server-generated identifiers; they cannot
  be linked retrospectively to the local UUID. Explicit review therefore asks
  the rider to check that the draft is not already in their history.
  Missing-file drafts remain blocked. Failed attempts have persistent local
  status; an online listener also resumes synchronization without Background Sync.
- Cold offline fallback documents load only fixed public CSS and a small local
  IndexedDB recovery script. Their CSP forbids connections; this script counts,
  exports and discards local drafts without account data, HTML insertion or POSTs.

Original-language content:

- User-entered names, descriptions, comments, historic reminder titles and
  records retain their original language.
- Official manual names, source notes and transcribed service terminology are
  source content; they are not machine translated or rewritten as new advice.
- Blog articles and community posts retain their original language, with an
  English disclosure in the blog interface.
- BRL amounts are never converted merely because the language changes.
- The account-deletion confirmation token remains `EXCLUIR`; English copy
  explicitly asks for that same token.
